# Frontend (`src/ui/PartyKing.UI/src`)

React 19, react-router, MUI + Tailwind v4, axios + SWR. Axios is configured in `src/service/request.ts`; the `@/` import alias maps to `src/`.

## Contents

- Routes and pages
- Session page (music, slideshow, settings)
- API base URL and polling
- BAC calculator
- Language (i18n)

## Routes and pages

`router/routes.tsx`:
- `/` Home lists sessions with a code search (no slideshow links).
- `/s/:sessionId` `MusicQueue`, the one page of a session.
- `/callback` is the Spotify redirect.
- `/admin` is the admin login and session panel (create, copy link, release host, delete). Rename, password and slideshow settings live on the session page. It shows the login form to a visitor and a notice to a signed-in user who is not an admin.
- `/admin/users` (`AdminUsers`) lists the registered users, a page of 20 at a time, with a debounced username search and a reset-password dialog per user. Admin only.
- Accounts: `AppHeader` (in `Layout`, so on every page, fixed in the upper-right corner at z-40 like the language switcher in the other one, hidden in a dev-embedded panel) holds a home icon that links to all the sessions (not on the landing page), `BacCalculatorButton` (see "BAC calculator" below) and `AccountMenu`, which is "Log in" for a visitor, which opens `AccountDialog` (log in / sign up). Signed in, it is the username with a person icon and drops a `MenuButton` with "Account settings" (the same dialog: change password, log out everywhere, delete account) and "Log out". Every `useAccount` caller shares the login hint (`usePersistedFlag` syncs all components using a key), so a login made in the admin page's own form shows in the corner at once. `useAccount` (`service/endpoints/account`) says who is signed in; see `features/sessions-and-auth.md`.
- `/dev/s/:sessionId/resistance` (dev builds only) shows 5 to 10 Resistance players side by side in one tab, see "Dev personas" in `features/sessions-and-auth.md`.
- `/s/:sessionId/games/...` see `games/`. The old `/s/:sessionId/upload` redirects to the upload dialog.

## Session page (`MusicQueue`)

- Everyone sees `NowPlayingCard` (art, title, artist, paused badge) and the queue. The viewer's role from `useViewerRole` (`GET /sessions/{id}/me`) adds:
  - For the host and any admin: a red delete icon on each "Up next" row (`Queue` prop `canRemove`, deletes at once, no confirmation).
  - For the host: `HostPlayer`, which plays the music, so the host must keep the page open. It needs no Spotify login for YouTube songs: it asks for the Spotify token (and mounts `SpotifyPlayer`) only once a Spotify song is playing, now playing or queued, and from then on keeps it. A 401 for that token goes to the Spotify login while the music has not started, and shows a message (reload to log in) once it plays, so a Spotify song queued mid-party never cuts the music. `VolumeControl` sets the volume, stored in `localStorage` through `usePersistedNumber` (`usePlayerVolume`, `partyking.volume`), which follows the `storage` event, so another tab of the same browser (the Resistance queue panel) changes the volume of the playing tab. A YouTube player error skips to the next song, but only until 2 videos fail in a row; then it stops and shows a message until the host presses "Next song" or a song plays. `ErrorLog` lists errors for the admin only.
  - For an admin who is not the host: `RemotePlayerControls` (Play/Pause through `POST player/commands`; Next through the admin endpoint for an admin, or the host's own for a host who is not an admin; disabled while no player is connected; optional volume when given one).
- A host whose login expired uses "I'm the host" in `SessionHeader` to log in again. `SessionHeader` also shows, to the host and admins, a gear (`SessionSettings`, a MUI `Dialog` with `SessionNameForm`, `SessionPasswordChangeForm`, `FallbackPlaylistForm` (the host's Spotify playlists and the account's saved ones in one list-and-Save form, see "Fallback playlist" in `features/music.md`) and `SlideshowSettingsForm`). To any signed-in account (`useAccount`) it also shows a save-as-playlist icon (`SaveQueueAsPlaylist`, see `features/music.md`).
- **Slideshow**: there is no separate slideshow route. The host and admins get `SlideshowView` in a left drawer that is open by default (closed by default on a touch device, `isMobileDevice`) and hidden with a toggle (persisted in `localStorage` through `usePersistedFlag`). `SlideshowView` fills its parent's box; guests never request the photos from this page.
- **Maximize**: a button opens `MaximizedView`, a `fixed inset-0` overlay with the slideshow, `NowPlayingOverlay` (title and artist only) and a read-only `QueueList`. The queue sits on the right on a landscape or wide screen (a phone turned sideways included) and below the slideshow on a portrait one; a queue button next to the X hides it (kept in `localStorage` as `partyking.maximizedQueueOpen`). Esc or the X exits. The overlay covers the page without unmounting it, so the host's `HostPlayer` keeps playing.

## API base URL and polling

- The API base URL comes from `src/envVariables.ts`: `VITE_API_URL` if set, else `http://127.0.0.1:4200` in dev (must match the API launch profile) and `/api` in production builds. To test from phones on the LAN, change both `envVariables.ts` (or set `VITE_API_URL`) and `src/api/PartyKing.API/Properties/launchSettings.json` to the machine's LAN IP, but don't commit that change.
- SWR `refreshInterval`s: slide 60 s with the hub connected and 5 s without (`SlideChanged` is pushed), queue 5 s, now-playing 4 s, session 30 s, session lists 10 s. The host player reports state every 10 s (and on every change) with an 8 s timeout.

## BAC calculator (`components/Bac`)

- A cocktail icon in `AppHeader`, for everybody (a visitor too, on every page, the landing page included), opens `BacCalculatorDialog` (MUI `Dialog`, full screen on a phone, so no route and the host's player on the session page keeps playing). Everything is computed in the browser; the API is not involved.
- `bacCalculation.ts` is the pure core: Widmark's formula run minute by minute over the drinks, so a gap between drinks (the blood reaching zero) is handled and the result is now, the peak and when the blood is clear. A drink is absorbed evenly over 30 minutes (`ABSORPTION_MINUTES`) and the body clears 0.15‰ an hour (`ELIMINATION_PER_HOUR`; NIST's average is 0.18). The factor is the average of the sex (0.68 / 0.55) or, once both the height and the age are given, Watson's total body water over 0.8 of the weight. The age term of Watson's male equation is 0.09516 (some sites print 0.09156).
- The estimate is in promille (g/kg). `bacUnits.ts` picks the unit by the UI language: Polish shows ‰ with the Polish limits (0.2‰ after alcohol, 0.5‰ drunkenness), anything else % (g/dL, so ÷10) with the US 0.08%. The dialog carries a disclaimer: it is not a tool to decide whether to drive.
- The warning about how far the estimate can be trusted is behind an "i" icon next to the close button in the dialog title (`BacInfoButton`, a MUI `Popover`), not on the page.
- Two collapsible sections (`BacSection`: a bordered box with a header that is one button across the whole width, arrow at its right end, and a darker panel; the content stays mounted and only hidden, so half-typed values survive): "About you" (`BacProfileForm`) and "Drinks" (`BacDrinkList`), put together by `BacSections`. The only required data is the weight (the sex has a default). Their starting state is decided when the dialog opens (MUI unmounts the content on close): "About you" is open until there is a valid weight and shut once there is (its header shows only the title); "Drinks" cannot be opened without a weight and is open by default once there is one. Filling the weight during an opening enables "Drinks" but does not open it, and clearing the weight shuts it again. Once there are drinks, the header of "Drinks" shows the pure alcohol of all of them in grams (`totalGramsOfAlcohol`, e.g. "32.3 g of alcohol"); without a weight it shows why the section is locked instead.
- Metric units only. Every number field is a `WheelNumberInput` (`components/common`): the mouse wheel adds or takes off a step (`stepNumber` in `utils/numberInput.ts`, within the min and max), but only in the focused field, so scrolling the dialog past a number never changes it. React's wheel handler is passive and cannot stop the page scrolling, so the component adds a native `wheel` listener with `passive: false`.
- Drinks: `BacAddDrink` is a small form (a kind fills in its usual serving, then volume, strength and time can be changed in one row that ends with a small amber + icon) that puts a drink on the list; the list shows the drink started last on top (`newestFirst`) in a panel of about ten entries that scrolls when the list is longer, and its entries (`BacDrinkEntry`, a line like "500 ml · 5% · 19.7 g · 20 min ago (22:43)": volume, strength, grams of pure alcohol, time) are read-only and have icons: edit (the fields open in place, saved with the check or dropped with the cross), delete, and "add another now" (`drinkAgain`: the same values, started now, for noting a round quickly). A time is entered as minutes ago, or on a clock (`datetime-local`) with the "Pick the exact time" switch. `bacDrinkDraft.ts` holds the draft logic: minutes ago count from the moment the draft is saved, and an entry edited without touching its time keeps its start. `bacTime.ts` converts the times.
- Persistence: `useBacState` keeps the profile, the drinks and the switch as one versioned JSON in `localStorage` (`partyking.bacCalculator`, `bacStorage.ts`). A field out of its range is dropped alone, drinks older than 24 hours are forgotten, and broken JSON or blocked storage gives the empty form. Drinks keep their start time, so an old list decays on its own.

## Language (i18n)

- The UI is English or Polish (English by default, no browser detection). The UI sends `Accept-Language: en|pl` on every request (request interceptor in `service/interceptors/request.ts`, read at call time).
- Server side: `UiLanguageParser` (`PartyKing.Application/Localization`) maps the header to `UiLanguage` (`En` / `Pl`: highest `q`, first on a tie, `pl-PL` counts as `pl`, anything else or no header gives English). `CoreController.GetLanguage()` reads it and controllers pass it to the Application services as a parameter, so Application never sees HTTP.
- Only the texts the server generates are localized: `GameService` (game names and descriptions; Ringo and Resistance keep their names, Never have I ever is "Nigdy w życiu" in Polish) and the two suggestion services (per-language prompt, avoid-repeats line and built-in fallback list in a private `Texts` record). Error messages (`Error.*` descriptions, ProblemDetails `title`) stay in English. `useGames` puts the language in its SWR key, so a switch refetches the names.
- UI texts: `i18next` with bundled `en.json` / `pl.json` (`src/i18n`; keys are type-checked against `en.json`; `i18n.test.ts` checks both files have the same keys). **New texts need a key in both files.** The choice lives in `localStorage` as `partyking.language`; the switcher is fixed in the upper-left corner (`LanguageSwitcher`, rendered by `Layout`).
- Every UI text goes through `t()`. Outside components (`resistancePhase.ts`, `resistanceRules.ts`, `ringoCards.ts`) texts come from `i18n.t` called lazily, `PLOT_CARDS` exposes `name` / `effect` as getters, and a component that only calls such helpers still calls `useTranslation()` so it re-renders on a language switch. The SVG labels in `ResistanceIcons` render through a small `T` component. The English Resistance texts were drafted from the Polish rules in `CLAUDE.local.md`.
- Tests run in English; a test that needs Polish calls `await setLanguage('pl')` (`testSetup.ts` resets it).
